Runtime systems / 03

Native APIs.
Small, useful pieces.

The runtime connects NEXUS programs to windows, input, drawing and system services. The standard library adds thin wrappers around concrete functionality that exists in the repository today.

Graphics

Start with a native window

The current runtime includes SDL-backed window/event handling and a set of immediate drawing helpers. The 2D surface includes rectangles, circles, lines, text, textures, fonts and a CPU-side raster canvas. It is suitable for compact utilities and prototypes.

fn main() {
    let ok = gfx_init(1000, 640, "NEXUS App")
    if !ok {
        print("Runtime unavailable: " + gfx_error())
        return
    }

    while !gfx_should_close() {
        gfx_poll()
        if gfx_key_down("ESC") {
            break
        }
        gfx_begin()
        gfx_clear(0.035, 0.045, 0.08, 1.0)
        gfx_rect(40.0, 40.0, 920.0, 110.0, 0.07, 0.12, 0.22, 1.0)
        gfx_text(70.0, 70.0, 3.0, "NEXUS APP", 0.55, 0.9, 1.0, 1.0)
        gfx_end()
    }
    gfx_shutdown()
}

For a ready scaffold, run nexus new MyApp --template app. Runtime dependencies must be available for the selected platform. The Windows portable package includes the bundled runtime DLLs.

Interaction

Input and optional audio

Input helpers expose keyboard and mouse state, plus the most recent event. Audio is dynamically loaded and may be unavailable if the corresponding runtime support or device is missing.

The 3D API currently provides a camera setup, grid, coloured cubes and experimental model loading through a compatibility OpenGL path. Treat this as an experimental rendering surface rather than a modern production engine.

Standard library

Concrete wrappers, not imaginary modules

Standard-library files add small named functions. Import a module and call the declared functions directly; do not assume an object-oriented namespace or generic container API that is not present in the source.

Game helpers

2D building blocks

For small games and interactive experiments the repository includes bounded tilemap storage, viewport-aware tile drawing, AABB/circle tests, tile movement helpers, lightweight platformer physics, sprite sheets, 2D camera transforms, frame animation and easing utilities.

These are focused helper systems, not a complete engine. An ECS, scenes, particles and UI helpers are also present but remain deliberately small.

Current boundaries

Know what is experimental

There is no claim of production chunk meshing, GPU mesh batching, modern shader management, job scheduling, terrain-noise systems or compressed chunk persistence. A production voxel engine is roadmap work. Some graphics/audio capabilities depend on optional platform runtime components.
