Compiler architecture

Two backends, different coverage

Backend A

Built-in x86-64 emitter

Emits PE32+ for Windows and ELF64 for Linux for a defined subset. It focuses on direct compilation of supported primitive operations and does not require a separately installed C++ compiler for those programs.

Backend B

LLVM / Clang path

Generates LLVM IR and uses a compatible Clang-style toolchain. This path handles broader fixed-width scalar, slice and runtime requirements. Toolchain configuration remains target-dependent.

Do not assume parity: a construct accepted by the frontend may still be unsupported by one backend. Use nexus explain-backend and the detailed backend-support matrix before selecting a deployment target.
Editor integrations

Use the editor you already have

The repository includes a VS Code extension source tree with NEXUS syntax support and a command to show the language-server output channel. The extension is packaged as a VSIX on the downloads page; it is not currently listed in the VS Code Marketplace.

NEXUS Studio is a separate Electron desktop workspace with a project explorer, Ace editor, integrated terminal and Build/Run actions. It does not bundle the compiler and does not currently include a debugger or a full diagnostics/refactoring panel.

Release engineering

Reproducible checks in CI

Repository workflows run formatting, lint, negative and differential compiler tests, sanitizer checks, fuzz smoke tests, secret scanning and platform build jobs. Website publication is independent of the slower Windows package job, so site changes do not have to wait for an installer rebuild.
