Explicit boundaries.

NEXUS is an actively developed compiled language. The compiler implements functions, structs, enums, arrays, imports, control flow, pointers and a growing set of fixed-width numeric and slice types.

Syntax / Hello

A program starts with main

fn main() {
    print("Hello from NEXUS!")
}

Functions use typed parameters and optional return types. Initialized bindings can infer their type; use let mut for a mutable binding.

The aliases int, isize and usize still mean i64; float means f64. Numeric types do not implicitly convert between widths.

Functions & data

Typed functions, structs and enums

fn add(a: i64, b: i64) -> i64 {
    return a + b
}

fn main() {
    let mut total: i64 = 0
    for i in 0..3 {
        total = total + add(i, 10)
    }
    print(total)
}

Structs and enums are supported, including unit variants and a bounded one-scalar enum payload. Imports resolve project-relative source modules.

Control flow

Branches, loops and match

The parser supports if / else, while, for ... in, break, continue and statement-form match. Ranges are half-open: the end bound is excluded.

for value in 0..5 {
    if value == 3 {
        continue
    }
    print(value)
}

match ready {
    true => { print("ready") }
    false => { print("waiting") }
}
Memory views

Read-only and mutable slices

A []T slice is a non-owning pointer-plus-length view. A mutable slice requires an explicit exclusive borrow from a mutable array. The lexical borrow ends at its closing scope.

fn set_first(values: mut []i64) {
    values[0] = 42
}

fn main() {
    let mut data: [i64; 3] = [1, 2, 3]
    {
        let mut view: mut []i64 = mut data[1..3]
        view[0] = 20
    }
    print(data[1])
}
Backend note: slices and the wider fixed-width scalar set use the LLVM path. The built-in x86-64 backend intentionally supports a smaller documented subset; --backend auto can select LLVM for supported language features.
Honest status

What is not implemented

Generic types, traits, closures, async, Rust-style impl blocks and a complete FFI model are not part of the current parser. There is no general-purpose generic Option<T> or Result<T,E> type system. Raw pointers and FFI are not protected by the slice borrow rules.
